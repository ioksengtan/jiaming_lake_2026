# 山屋時光需求

這一輪只把需求寫進倉庫，沒有計時器頁面，也沒有程式。

產品名稱是「山屋時光」。嘉明湖是這條路線的副標，出現在頁面標題、分頁標題前綴、小卡與里程碑卡上。不要再用「嘉明湖倒數山」當產品名稱。

## 資料來源

寫這份文件時，手上有這些材料：

- 上傳的投票結論：九個候選收斂成一頁專注計時，以及後來被劃掉的通勤入口、照片跳出、真實天色、實體燈與其他分支。
- 上傳的六題投票結果：回程分鐘數、回程發卡、下一座想爬哪裡、離山屋多近算進山屋、小卡一句話、產品名稱。
- 擁有者已寫死的範圍，含下面六項定案。

委託裡點名要一併納入 `mountain-timer-spec-menu.md` 與 `mountain-timer-spec-answers.md`。寫這份文件時，倉庫和上傳區都沒有這兩個檔。下面沒有逐字收錄它們。若之後補上，要再對一次，把檔案裡有、這裡沒有的句子補進來。

六項定案如下：

| 項目 | 定案 |
|---|---|
| 產品名稱 | 山屋時光。嘉明湖是路線副標 |
| 回程時間 | 回程下山另算一百分鐘，加在去程四百分鐘之外，全程五百分鐘 |
| 回程發卡 | 回程不發小卡。只有回到登山口才給里程碑卡 |
| 下一座想爬哪裡 | 三選一：玉山主峰、雪山主峰、合歡山。只記錄點擊，存在瀏覽器本機 |
| 進山屋 | 按「我被打斷了」時，離下一座山屋剩不到十分鐘路程才進山屋，其餘坐在路邊喝水 |
| 小卡主句 | 主句寫路線位置事實。下方小字放使用者的累積分鐘與專注次數 |

投票裡「回到登山口」沒有寫死是哪一個登山口。擁有者舉的例子用了「向陽登山口」。軌跡檔裡的登山口是戒茂斯登山口，沒有向陽登山口。地名以〈軌跡檔核對〉為準，不把例子裡的地名當成這條路線的事實。

## 產品目標與不做的事

山屋時光把一段專注時間，走成戒茂斯線上的一段路。去程與回程接在同一條進度上。進度留在瀏覽器本機，今天走一段，明天從上次停下的地方接著走，不必每次從登山口重來。走完去程再走完回程、回到登山口，才算這趟走完。

這一版要讓人在手機與電腦上都用一頁看完：溫暖、手繪、近乎靜止的山，一個小登山者沿著真實剖面移動。陡坡走得慢，緩坡走得快。時間到了，走完的是這一段應走的路，不是一把與地形無關的直線。

不做的事：

- 不做通勤入口，不做「輸入這趟通勤分鐘數」，不做轉乘點或山屋當車站。
- 不做帳號、登入、雲端同步、軌跡匯入、交通資料。
- 不做第二條路線。玉山主峰、雪山主峰、合歡山只記點擊。
- 不做照片在當年時間點跳出，不做背景跟著真實天色換晨霧、午後、夕陽或銀河。
- 不做實體桌上燈、木片或燈條，不做孩子的紙山，不做一起爬，不做會議山。
- 回程「把走過的節點收進背包」只差一票，這一版不做，留待以後。
- 不做音效，不做結束提示音，不做通知。
- 不使用任何商品的品牌名或原圖。
- 不寫湖怎麼形成，不寫排名。海拔與距離只有〈軌跡檔核對〉允許的才印。
- 公開頁面、卡片與標題不要寫委託者或隊友的英文姓名。若需要作者，只寫 ioksengtan。
- 不捏造剖面、山屋、海拔或距離。資料對不上就標待確認，頁面上不印。

頁面本身要是純前端靜態檔，不靠建置步驟才能打開。用相對路徑，讓它在 GitHub Pages 的 `/jiaming_lake_2026/` 底下也能開啟。高度剖面在寫頁面之前先從軌跡檔算好，收成小型資料寫進頁面；執行時不要去解析整份路線檔。

遊記首頁若結構放得下，加一個不顯眼的文字連結到這一頁。放不下就只在說明裡寫網址。

介面文字用繁體中文，名詞寫完整，例如「分鐘」「公尺」「公里」「營地」，不要自行縮成「分」或外文單位。

## 路線與節點

全程是這份倉庫裡的戒茂斯線原路來回：戒茂斯登山口走到嘉明湖，再沿同一條剖面折返到戒茂斯登山口。

`data/route.json` 只存單程。回程不是第二份軌跡，而是同一條線倒著走。這是遊記已確認的走法（見 `DECISIONS.md`），也是網頁原本對回程的處理。沒有另外一條回程軌跡檔。

節點只採用倉庫裡寫得清楚的地方。規格說的「山屋」，在這份軌跡上沒有同名點。休息點目前是營地，頁面上就寫營地，不要改叫山屋。

這一版可以當成節點的地方：

| 角色 | 名稱 | 頁面怎麼用 |
|---|---|---|
| 起點，也是里程碑的終點 | 戒茂斯登山口 | 出發與回到這裡。不發小卡 |
| 去程休息點 | 新武呂溪營地 | 走到才發一張小卡。中斷時可以當「下一座」 |
| 去程休息點 | 足球場營地 | 同上 |
| 去程休息點 | 妹池營地 | 名稱可以用。位置有兩筆數字，見核對節，距離與海拔先不印 |
| 轉折，不是山屋 | 嘉明湖 | 經過時畫面有一點小變化。不發小卡。湖的海拔待確認，不印 |
| 路線上的山頭，不是休息點 | 戒茂斯山前峰 | 不發小卡，也不當中斷時要進去的山屋 |

下面這些不要寫進頁面，也不要拿來發小卡，原因在核對節：

- 向陽登山口、向陽山屋：軌跡檔裡沒有。
- 嘉明湖山屋：開放街圖的說明點離這條線約三公里，不是這條路線上的點。
- 排球球場營地、獵寮營地：原始地圖資料裡有名字，但沒有收進路線航點，排序與距離待確認。
- 三叉山、戒茂斯山、向陽山北峰：不在這條走線上，不當節點。

小卡主句要寫這條路線上站得住的位置事實，句型像「從戒茂斯登山口出發後的第一座營地」。例子若寫成「從向陽登山口出發後的第一座山屋」，只是在示範句型，不是這條線的事實，不能照抄。

在排球球場營地與獵寮營地還沒確認之前，不要把足球場或妹池寫成「第幾座」。新武呂溪營地是路線航點裡、登山口之後的第一座營地，這句目前寫得下去。

## 時間換算表

去程與回程的分鐘數分開算，再接成同一條進度。

| 項目 | 分鐘 |
|---|---|
| 去程，戒茂斯登山口到嘉明湖 | 400 |
| 回程，嘉明湖折返到戒茂斯登山口 | 100 |
| 來回合計 | 500 |

單次專注只做三個長度，預設二十五分鐘：

| 單次專注 | 若每次都選這個長度，走完五百分鐘要幾次 |
|---|---|
| 15 分鐘 | 33 次是 495 分鐘，還剩 5 分鐘。這 5 分鐘要怎麼走完，待確認。不要自行改成 34 次，也不要把全程改成 495 分鐘 |
| 25 分鐘（預設） | 20 次 |
| 50 分鐘 | 10 次 |

較早曾建議大約八到十二個專注時段走完全程。以預設的二十五分鐘來說，五百分鐘是二十次，對不上八到十二。這一版以五百分鐘為準。

換算規則：

- 使用者選的十五、二十五或五十分鐘，就是這一段在五百分鐘進度上前進的分鐘數。一段結束時，前進的分鐘數要正好等於所選分鐘數。
- 去程累積滿四百分鐘才到嘉明湖。回程再累積一百分鐘才回到戒茂斯登山口。兩段不要混成同一個四百或五百的池子再重分。
- 陡坡走得慢，緩坡走得快。同樣一分鐘，陡的地方沿著路線前進的距離較短，緩的地方較長。原則是用累積爬升與距離一起算，不是只按距離平均切。
- 坡度要怎麼換成每一公尺幾分鐘，規格沒有給公式，待確認。確認之前，總分鐘數仍必須是去程四百分鐘、回程一百分鐘，不可另定一套總時間。
- 「剩不到十分鐘才進山屋」的十分鐘，用的是上面這套路線分鐘，不是另外估算的步行時間。
- 進度存在瀏覽器本機儲存（`localStorage`）。重新整理、關掉分頁後再打開，已走的分鐘數、專注次數與已獲得的卡都還在。
- 要有重新開始全程的做法。放在不顯眼的地方，按下去之前要再確認一次。確認後才清除進度、專注次數與卡片。三座山的點擊紀錄不必跟著清掉。

測試可以留一個網址參數，把一段專注的實際等待縮短，用來檢查跨時段累積，以及重新整理後進度還在。這個參數不要出現在介面上。

## 暫停與中斷規則

計時進行中可以開始、中斷、重設。中斷的按鈕文字是「我被打斷了」。

- 按下「我被打斷了」：這一小段先停住。已經走掉的進度留下，不扣、不算失敗。回來後從停下的進度接著爬，不從登山口重來，也不從山屋重算。
- 若往前進方向、離下一座已確認的休息點還剩不到十分鐘路線時間，小登山者進那一座休息點等候。
- 其餘情況，包含下一座還很遠、下一座位置仍待確認、或前面已經沒有休息點，小登山者坐在當下的路邊喝水。不要為了這張畫面把他送到還沒確認的點，也不要送到規格裡沒有的山屋。
- 進休息點等候只是停下時的畫面。沒有真正走到那個點之前，不發那張小卡，也不把進度加成已經抵達。
- 重設只結束這一小段的剩餘時間，不把已經累積的路程扣回去。整趟清除只走「重新開始全程」，而且要確認。
- 分頁切走或螢幕鎖定時，若人沒有按「我被打斷了」，計時不要暫停，也不要因為瀏覽器把計時器變慢而少算。回到頁面時，用實際經過的時間補上進度。
- 中斷之後關掉頁面再打開，仍停在中斷，登山者仍在剛才的休息點或路邊，進度與中斷前相同。

## 畫面與動態規則

一頁。手機寬度三百九十像素、高度八百四十四像素，以及電腦寬度一千二百八十像素、高度八百像素，都要一屏看完，沒有橫向捲動。三百九十像素寬時，`document.documentElement.scrollWidth` 應等於三百九十。

畫面是溫暖的手繪感，可以用可縮放向量圖或畫布的筆觸，顏色柔和。山的形狀只用軌跡檔算出的高度剖面，不要另畫一座看起來像資料、其實是裝飾的山。遠景若要有天空或紙張質地，不要冒充路線。

小登山者沿著剖面前進。去程由登山口走向嘉明湖，回程沿同一條稜線走回登山口。姿勢近乎靜態插畫，不要走路循環，不要閃爍。只有經過已確認的營地或嘉明湖時，才有一點小小的、停得住的變化，例如營地記號亮起、湖邊出現一小塊水面。不要循環動畫。

剩餘時間要看得清楚，但不要比山更大、更搶。

專注長度在畫面上只提供十五分鐘、二十五分鐘、五十分鐘，預設二十五分鐘。不要做成自由輸入，也不要做成其他模式。

「下一座想爬哪裡」放在同一頁，三個選擇：玉山主峰、雪山主峰、合歡山。點了只寫進瀏覽器本機，不開啟新路線，不改變這座山的形狀。

## 卡片與收集簿

走到一座已確認的去程休息點，給一張小卡。回程再經過同一點，不發第二張。

小卡要好看到像一張可以留下的作品，用網頁畫布畫，不要貼上別的商品的圖。

小卡上要有：

- 產品名稱「山屋時光」，副標「嘉明湖」。
- 主句：路線位置事實，用核對節允許的地名與順序。
- 主句下方的小字：走到這一點時，使用者已經累積的專注分鐘數，以及專注次數。
- 這一條路線的手繪稜線，形狀來自剖面。還沒走到的部分可以較淡，不要改高度。
- 完成這張卡的日期，用台北時間，放在小字，不放進主句。

海拔、沿路線距離、排名，只有核對節寫明可以印的才印。待確認的不印，也不要用看起來很準的四捨五入代替。不寫湖的形成原因。

每一張卡都可以存成 PNG 圖檔下載。手機上要能分享，或長按圖片儲存。

已獲得的卡收在同一頁的收集簿裡，預設收合，打開後仍在這一屏裡看，不要把整頁拉長到必須往下捲。可以一張一張看。里程碑卡也放進同一本收集簿。

## 回程與里程碑卡

回程從嘉明湖沿原剖面折返，時間是另外的一百分鐘，陡坡仍走得慢，緩坡仍走得快，合計正好一百分鐘。

回程不發小卡。經過營地與湖邊時，不要再發一張，也不要閃爍。去程已經亮起的記號可以留著。

只有進度走滿五百分鐘、人回到戒茂斯登山口，才給里程碑卡。不要在抵達嘉明湖時給，也不要在稜線最高點給。規格例句裡的「回到向陽登山口」與軌跡不符，里程碑的地點寫戒茂斯登山口。

里程碑卡同樣用「山屋時光」與副標「嘉明湖」，並且要有：

- 路線名：戒茂斯線。
- 主句：回到戒茂斯登山口這件路線事實。可以寫走去嘉明湖再折返，但不要寫向陽。
- 手繪稜線：整段去程剖面，含湖前的高點與稍降到湖邊的形狀，不要修成終點最高。
- 小字：走完時的累積分鐘與專注次數。走完應是累積五百分鐘。
- 日期，規則與小卡相同。

累積爬升若要印，只印核對節允許的數字，並註明是這份路線檔的數字或折返推算，不要寫成另一份實測。海拔同樣。排名不印。不寫湖的形成原因。

里程碑卡也要能存圖，並收進收集簿。

## 驗收標準

這一輪的拉取請求只收這份需求，不要求截圖，也不合併。

以後做出頁面時，至少要自己檢查這些事，並寫進該次拉取請求：

- 手機三百九十乘八百四十四像素，以及電腦一千二百八十乘八百像素，各有開始前的畫面。進行中、在休息點等候、坐在路邊喝水、一張小卡、一張里程碑卡，都要能在手機寬度裡一屏看完。
- 三百九十像素寬時，`document.documentElement.scrollWidth` 等於三百九十。兩個尺寸都沒有橫向捲動，也不必往下拉才看得完主要畫面。收集簿打開後仍在這一屏裡。
- 用測試參數把專注縮短，連續走完不只一段。重新整理後，累積分鐘、登山者位置與已獲得的卡還在。
- 走滿去程四百分鐘時人在嘉明湖，沒有里程碑卡。再走滿回程一百分鐘時人在戒茂斯登山口，才出現里程碑卡。
- 在離下一座已確認休息點不到十分鐘時按「我被打斷了」，人在該休息點等候，進度沒有被加成抵達，也沒有少掉。離得更遠時按下去，人坐在路邊喝水。
- 分頁切走或把等待拉長後回來，進度等於實際經過的時間，沒有因為節流變慢。
- 頁面上沒有音效、沒有通勤入口、沒有第二條路線，也沒有待確認的海拔、距離或排名。
- 產品名稱是山屋時光，嘉明湖只當副標。介面是繁體中文，名詞沒有自行縮寫。

## 先驗證的事

先確認人會不會因為「看山」而想用，再加別的功能。

- 連續幾天，會不會自己打開，從上次的進度接著走，而不是每次都重來。
- 看山與看卡片，是否比只看剩餘時間更想繼續。
- 走到營地、最後回到登山口，會不會想把卡存下來。
- 可以記每天打開幾次、有沒有存卡。這一版不要為此做帳號。
- 做卡之前先把核對節裡的待確認處理掉：妹池位置、嘉明湖要印哪一個海拔、排球球場營地與獵寮營地算不算休息點、十五分鐘走完後剩下的五分鐘。沒處理之前，對應的數字不要印。

## 軌跡檔核對

### 和規格不符或無法確認

- 規格例句與部分里程碑用詞是向陽登山口、山屋。軌跡是戒茂斯線，休息點叫做營地。頁面不要改寫成向陽，也不要把營地改叫山屋。
- 里程碑若寫「回到向陽登山口」會與軌跡不符。應寫回到戒茂斯登山口。
- 嘉明湖海拔至少有三個數字：遊記來源 3,310 公尺、路線終點 3,323 公尺、剖面上的最高點 3,353 公尺。待確認，卡片不印湖的海拔，也不要把終點畫成最高點。
- 妹池營地的航點自己註明是估計，又與開放街圖說明點差約三百公尺。待確認，不印妹池的海拔與距離。十分鐘門檻在這一站也先不要用未選定的那一筆。
- 排球球場營地、獵寮營地可能使「第幾座營地」的排序改變。待確認之前，小卡不要寫足球場或妹池是第幾座。
- 戒茂斯山前峰的標籤海拔與高程模型不一致。待確認，這張卡本來也不該為它而做。
- 路線點沒有時間戳記。照片與遊記段落的時間不能拿來當成走路進度的時間軸。
- 來回累積爬升 2,806 公尺是折返推算，不是獨立軌跡。
- 十五分鐘的倍數沒有整除五百分鐘，剩下的五分鐘待確認。
- 陡坡與緩坡的換算公式沒有給出數字，待確認。總時間仍是四百分鐘加一百分鐘。

卡片目前允許印出的數字，只有這些：

- 戒茂斯登山口海拔 1,919 公尺。路線起點與航點相同，可註明來自這份路線檔。
- 新武呂溪營地：沿路線 3,250 公尺，海拔 2,245 公尺。只有路線航點這一筆高程，印的時候註明是路線檔，不要寫成公告測量。
- 足球場營地：沿路線 5,550 公尺，海拔 2,783 公尺。路線航點與開放街圖營地節點落在同一點。
- 去程累積爬升 2,105 公尺，是路線檔寫明的上升。來回 2,806 公尺只在註明「原路折返推算」時可印。
